# Samostatný editor architektury

První záložka prostředí Projekt provádí kontrakt `docs/architektura-projektu.md`: přehled domén (`landing/`) → plátno 2, stránka jedné domény jako layout a logika (`page-editor/`, kontrakt `docs/navrhy/2026-11-10-platno-2.md`) → běžný Editor nad ID prvku (plátno 3). **Otevřít mapu domény** vede rovnou na plátno 2 první stránky domény; doména bez stránek ukáže prázdné plátno s výzvou, doména s více hosty (starší sdílená struktura) se neotevře a odkáže na oddělení hostu na přehledu. Struktura stránek (založení, podstránky, přejmenování, pořadí ↑ ↓, odstranění) se mění ve Struktuře v levém panelu plátna 2; přesun stránky pod jiného rodiče už editor nenabízí. „Projekt“ v textech znamená jen celý projekt (Architektura projektu), jedna doména je vždy „doména“. Plátno 2 má tři sloupce: Struktura a paleta vrstvy, stránka (hlavička se Skenovat web, Zkontrolovat plán a stavem stránky, přepínač 1 Layout / 2 Logika, drátový model z boxů se značkami a prvky logiky, pruh Další přípustný krok) a vpravo Detail boxu (`box-detail/`: stav, skica, inspirace, prvky boxu) nebo Detail prvku (`element-detail/`). Formulář stránky a domény a sdílená logika webu domény (stránky, cesty zákazníka, kontrola mapy) jsou v `domain-site/`; editor sekcí stránky (`page-sections/`) sdílí formulář stránky i záložka Stránka v Detailu. Pracovní zadání se v Detailu jen čte; upravuje se v běžném Editoru nad stejným ID („Otevřít v Editoru“). Tmavé barvy a tokeny vrstev (`--ae-tone-*`) jsou definované na kořeni `.architecture-editor` v `styles/architecture-editor.css` a platí jen pro tuto feature.

**Pravidla zápisu** (`docs/domeny-a-worktree.md` §4, F1): architektura (domény, stránky, pořadí, přesun, oddělení hostu) je zapisovatelná i na Git mainu, když pohled vrací `architectureEditable`; layout stránky (`site.sections` s boxy) patří ke struktuře; obsah stránky (prvky logiky: vložení, přesun mezi boxy, odebrání) zůstává na mainu jen pro čtení (`readOnly`). `logic/edit-locks.ts` počítá dva zámky (`structureLock`, `contentLock`) a každý nese větu, proč je úprava zakázaná (ukládání, načítání, chyba, rozpracované odstranění, uzavřená karta, obsah mainu). Trvalé důvody stojí pod hlavičkou (`landing/components/DomainLockNote`, skládá `components/EditorNotices`); ukládání a načítání pluje v pravém dolním rohu bez posunu plátna a bez zachytávání kliknutí. Po dokončení zmizí samo. Zápis jde dál přes `/api/graph` a `/api/canvas-plan`; backend složený graf rozdělí na architekturu a obsah. Rozdíly obsahu worktree proti architektuře (`view.conflicts`) ukáže `view-conflicts/`.

Editor se klíčuje jen projektem (`project/workspace/components/ProjectWorkspace.tsx`): přepnutí worktree nechá otevřenou doménu, stránku, vybraný prvek i hierarchický editor (stav i URL), jen `useArchitectureGraph` a Desktop stav znovu načtou obsah nového prostoru. Rozpracované odstranění se při přepnutí zahodí. Adresu na rozsah převádí `logic/editor-route.ts` (test vedle).

Kontrolu mapy (`GET /api/project-architecture/map-check`) čte `logic/use-map-check.ts` při změně otisku grafu; `ArchitectureEditor` z ní spočítá díry otevřené domény a plátno 2 je pod **Zkontrolovat plán** zúží na otevřenou stránku (panel `domain-site/map-check/`); klik otevře stránku, vybere komponentu nebo zdroj hrany.

Živý stav domén (web a worktree, `live-status/`) načítá jen `logic/use-domain-live.ts`; `ArchitectureEditor` ho drží a rozdá přehledu a žetonu webu v hlavičce plátna 2, akce (přepnout worktree, nová relace, nový worktree) posílá nahoru do `App` přes `live`. Správu worktree (přiřazení k doméně `PATCH /api/workspaces/{wid}`, přesun do skladiště `POST /api/workspaces/{wid}/archive`, seznam skladiště) volá jen `logic/use-worktree-admin.ts`; po úspěchu obnoví stav práce a seznam prostorů v `App`.

`ArchitectureEditor` skládá dílky a jako jediný ukládá. Drží rozsah (`domainId`, `pageId`) a vybraný prvek (`architectureNode` = Detail prvku); obojí se zrcadlí do URL (starší `structureNode` se ignoruje a z adresy maže). Studio (tok podle `carries`, stav karet, dráhy cest) je samostatná záložka `frontend/project/studio/`; otevírá tento editor parametry `editorId`, `domainId`, `pageId`, `architectureNode`. Layout stránky ukládá `saveLayout` jednou změnou grafu (`setEditorPageLayout`: `site.sections` přes `setEditorPageSite`/`pageSiteForSave`, které drží `box` a `parent`; prvkům z odebraných boxů smaže `card.section`). Hlavička (`ArchitectureHeader`) ukazuje krok a drobečky „prostředí / host / stránka“, Export JSON, Obnovit a ID editoru jako kopírovatelný čip. Prvek z palety logiky vkládá přes `/api/canvas-plan` jako uzel s `element: { kind }` pod stránku a s `card.section` boxu (`createEditorElementPlan`); přesun mezi boxy je `setEditorNodeSection`, odebrání náhled a potvrzení odstranění. Kompletní stránka (`pageComplete`) přidá k zámku obsahu důvod „Stránka je kompletní“, dokud ji člověk v tomto sezení neotevře k úpravám (`reopened`). `useArchitectureGraph` načítá celý existující graf, předává jeho digest do zápisu a po vložení plánu ověřuje uložené identity z kanonického čtení. Změna zároveň obnoví graf a Desktop stav rodiče, aby návrat do běžného Editoru nezobrazil starou kopii. Konflikty neprovádějí automatický přepis; rozepsané hodnoty zůstávají dostupné. Odstranění stránky využívá existující preview, potvrzení a API odstranění včetně jeho lokální historie.

ID editoru domény má tvar `opora:architecture:v1:<project>:<workspace>:domain:<domainId>` s jednotlivě URI-kódovanými hodnotami. Je stabilní pro doménu v pracovním prostoru, nepředstavuje oprávnění ani druhé úložiště dat. URL `editorId` musí souhlasit se scope. Parametry architektury jsou nezávislé na `layer` a `node` běžného Editoru.

Nová doména je existující application sektor s vlastním ID a jedním záznamem prostředí/hostu. Produkční a vývojová doména tak mají samostatné stromy stránek, přestože jsou ve stejném projektovém grafu. Starší vícehostová aplikace zůstává výslovně označenou sdílenou strukturou. Vědomé oddělení jednoho hostu jej atomicky přesune do nového prázdného sektoru; původní stránky, specifikace a identity se neklonují ani nemažou.

Pořadí stránek vychází z uloženého pořadí v `graph.nodes`. Změna pořadí prohodí jen sourozenecké stránky. Kanonický kontext pro agenta a OporaHub obsahuje odvozenou `navigation` projekci s doménou, pořadím stránek a nejbližším rodičem stránky; běžné kontejnery jsou průhledné. Přesun nebo přerovnání běžných karet tuto projekci nemění. `page-path` normalizuje pouze právě odesílaný formulář; uložené cesty hromadně neopravuje.

Vazby se na plátně 2 nekreslí; vzniknou a mění se v běžném Editoru. Přechody pracovních fází nadále řídí původní workflow v běžném Editoru.

Čisté operace identity, rozsahu, vazeb, záměru a layoutu stránky (`setEditorPageSite`, `setEditorPageLayout`) mají testy vedle `logic/editor-model.ts`. Špatně nakreslenou vazbu (`next` mezi kartami, `flow` mezi oblastmi, `canRemoveEditorEdge`) člověk odebere odkazem „Odstranit vazbu“ v záložce Vazby detailu prvku; ten volá `removeEdge` v `ArchitectureEditor`: zámek obou konců, pak `/api/removal-preview` (`kind=edge`) a hned `/api/remove` s otiskem náhledu, bez dialogu (vazba nenese obsah karty a jde vrátit přes `recoveryId`; `/api/graph` mazání odmítá). Požadavky skládá `logic/edge-removal.ts` (test vedle). Úplný průchod (+ Stránka, šablona, posun a velikost boxu, prvky logiky do boxu a na celou stránku, obnovení) se ověřuje v prohlížeči nad izolovanými daty.
