# Samostatný editor architektury

První záložka prostředí Projekt provádí kontrakt `docs/architektura-projektu.md`: přehled domén (`landing/`) → Mapa domény (`domain-map/`) → Editor stránky (`page-editor/`). Struktura stránek, podstránky, pořadí a navigace se mění jen na Mapě domény. „Projekt“ v textech znamená jen celý projekt (Architektura projektu, Strom projektu), jedna doména je vždy „doména“. Editor stránky má čtyři sloupce: Strom projektu / Knihovna prvků, Mapa architektury (nad plátnem pruh navigace domény, úsek cesty zákazníka aktivní stránky a pruh sekcí; oblasti → sektory → uzly, podstránka jako odkaz na stránku), Hierarchický editor komponenty (`component-structure/`, otevře se dvojklikem nebo „Otevřít detail ↗“) a Detail prvku (`element-detail/`, kontext agenta, u stránky záložka Stránka, Zadání / Vazby / Práce). Editor sekcí stránky (`page-sections/`) sdílí formulář stránky na Mapě domény i záložka Stránka. Pracovní zadání se v Detailu jen čte; upravuje se v běžném Editoru nad stejným ID („Otevřít v Editoru“). Tmavé barvy a tokeny vrstev (`--ae-tone-*`) jsou definované na kořeni `.architecture-editor` v `styles/architecture-editor.css` a platí jen pro tuto feature.

**Pravidla zápisu** (`docs/domeny-a-worktree.md` §4, F1): architektura (domény, stránky, pořadí, přesun, oddělení hostu) je zapisovatelná i na Git mainu, když pohled vrací `architectureEditable`; obsah stránky (vložení z knihovny, přesun a vazby karet, oblasti, sektory) zůstává na mainu jen pro čtení (`readOnly`). `logic/edit-locks.ts` počítá dva zámky (`structureLock`, `contentLock`) a každý nese větu, proč je úprava zakázaná (ukládání, načítání, chyba, rozpracované odstranění, uzavřená karta, obsah mainu). Trvalé důvody stojí pod hlavičkou (`landing/components/DomainLockNote`, skládá `components/EditorNotices`); ukládání a načítání pluje v pravém dolním rohu bez posunu plátna a bez zachytávání kliknutí. Po dokončení zmizí samo. Zápis jde dál přes `/api/graph` a `/api/canvas-plan`; backend složený graf rozdělí na architekturu a obsah. Rozdíly obsahu worktree proti architektuře (`view.conflicts`) ukáže `view-conflicts/`.

Editor se klíčuje jen projektem (`project/workspace/components/ProjectWorkspace.tsx`): přepnutí worktree nechá otevřenou doménu, stránku, vybraný prvek i hierarchický editor (stav i URL), jen `useArchitectureGraph` a Desktop stav znovu načtou obsah nového prostoru. Rozpracované odstranění se při přepnutí zahodí. Adresu na rozsah převádí `logic/editor-route.ts` (test vedle).

Živý stav domén (web a worktree, `live-status/`) načítá jen `logic/use-domain-live.ts`; `ArchitectureEditor` ho drží a rozdá přehledu a mapě domény, akce (přepnout worktree, nová relace, nový worktree) posílá nahoru do `App` přes `live`. Správu worktree (přiřazení k doméně `PATCH /api/workspaces/{wid}`, přesun do skladiště `POST /api/workspaces/{wid}/archive`, seznam skladiště) volá jen `logic/use-worktree-admin.ts`; po úspěchu obnoví stav práce a seznam prostorů v `App`.

`ArchitectureEditor` skládá dílky a jako jediný ukládá. Drží rozsah (`domainId`, `pageId`), vybraný prvek (`architectureNode` = Detail prvku) a otevřený hierarchický editor (`structureNode`); vše se zrcadlí do URL. Nový uzel, sektor (i do oblasti – plán ho položí do rámu, plný rám backend sám zvětší a rodičem zůstane rodič oblasti) a oblast vkládá přes `/api/canvas-plan`. Hlavička (`ArchitectureHeader`) ukazuje krok a drobečky „prostředí / host / stránka“, Export JSON, Obnovit, v Editoru stránky + Oblast / + Sektor a ID editoru jako kopírovatelný čip. `useArchitectureGraph` načítá celý existující graf, předává jeho digest do zápisu a po vložení plánu ověřuje uložené identity z kanonického čtení. Změna zároveň obnoví graf a Desktop stav rodiče, aby návrat do běžného Editoru nezobrazil starou kopii. Konflikty neprovádějí automatický přepis; rozepsané hodnoty zůstávají dostupné. Odstranění stránky využívá existující preview, potvrzení a API odstranění včetně jeho lokální historie.

ID editoru domény má tvar `opora:architecture:v1:<project>:<workspace>:domain:<domainId>` s jednotlivě URI-kódovanými hodnotami. Je stabilní pro doménu v pracovním prostoru, nepředstavuje oprávnění ani druhé úložiště dat. URL `editorId` musí souhlasit se scope. Parametry architektury jsou nezávislé na `layer` a `node` běžného Editoru.

Nová doména je existující application sektor s vlastním ID a jedním záznamem prostředí/hostu. Produkční a vývojová doména tak mají samostatné stromy stránek, přestože jsou ve stejném projektovém grafu. Starší vícehostová aplikace zůstává výslovně označenou sdílenou strukturou. Vědomé oddělení jednoho hostu jej atomicky přesune do nového prázdného sektoru; původní stránky, specifikace a identity se neklonují ani nemažou.

Pořadí stránek vychází z uloženého pořadí v `graph.nodes`. Změna pořadí prohodí jen sourozenecké stránky. Kanonický kontext pro agenta a OporaHub obsahuje odvozenou `navigation` projekci s doménou, pořadím stránek a nejbližším rodičem stránky; běžné kontejnery jsou průhledné. Přesun nebo přerovnání běžných karet tuto projekci nemění. `page-path` normalizuje pouze právě odesílaný formulář; uložené cesty hromadně neopravuje.

Vazba uzlů a sektorů ukládá existující port `next` jako návaznost práce. Vazba dvou oblastí používá `flow`. Oblast sdružuje prvky geometricky; nepřidává druhou hierarchii rodičů. Přesun oblasti zachovává její členy a respektuje jejich uzavření. Přechody pracovních fází nadále řídí původní workflow v běžném Editoru.

Čisté operace identity, rozsahu, přesunu, vazeb a záměru stránky (`setEditorPageSite`) mají testy vedle `logic/editor-model.ts`. Úplný průchod tvorbou stránek, vložením z knihovny, úpravou zadání a obnovením adresy se ověřuje v prohlížeči nad izolovanými daty.
