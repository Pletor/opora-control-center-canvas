Prostředí Projekt spojuje zadání aplikací a stránek se skutečnými zdrojovými soubory a mapou Graphify. Strom zadání je projekce uzlů téhož grafu v aktuálním workspace, nikoli druhá databáze stránek. Zdrojový strom a mapy nadále popisují kód; samotná naplánovaná stránka není důkazem realizace.

Záložka **Architektura projektu** před Graphify-out otevírá přehled domén, Mapu projektu vybrané domény (jediné místo, kde se mění stránky a jejich pořadí) a Editor stránky v `architecture-editor/`. Editor stránky má Strom projektu / Knihovnu prvků, Mapu architektury, Hierarchický editor komponenty a Detail prvku (kontext agenta, Zadání / Vazby / Práce; název a účel jde opravit přímo). Má vlastní tmavý rám, navigaci, plátno a karty; nepřipojuje běžný `App.workspace-shell`, `Board` ani `NodePanel`. Běžný Editor zůstává místem pro pracovní zadání (`spec`) nad stejnými grafovými identitami. Stabilní ID mapy je odvozené z projektu, pracovního prostoru a domény. Mapy kódu a zdrojové soubory zůstávají dostupné v původních záložkách.

Aplikace je sektor s `site.kind = "application"` a seznamem prostředí (`name`, `host`). Nová doména má vlastní sektor s jedním prostředím/hostem a samostatný strom stránek. Starší aplikace s více hosty zůstává označenou sdílenou strukturou, dokud člověk výslovně neoddělí host do nové prázdné domény. Stránka je uzel s `site.kind = "page"` a cestou `path`; patří nejbližšímu předku aplikace a může obsahovat další stránky i běžné komponenty. Domény se zde evidují, nekonfiguruje se DNS ani nasazení.

Účel aplikace i stránky žije pouze v `node.purpose`. Pracovní zadání v `spec.goal` se doplňuje samostatně v Editoru a změna účelu ho nepřepisuje. Struktura stránek, jejich pořadí a rodiče se upravují na mapě domény; ostatní stromové projekce slouží navigaci. Editor stránky vkládá dílky do obsahu konkrétní stránky nebo jejího potomka. Jména, hosty, cesty a účel se opravují na stejné identitě, bez mazání potomků.

Git `main` zůstává pouze ke čtení. Před úpravou se uživatel výslovně přepne do existujícího pracovního prostoru nebo vytvoří worktree; lokální a prázdný projekt používá `draft`. Žádný zápis se potichu nepřesměruje do jiného workspace.
