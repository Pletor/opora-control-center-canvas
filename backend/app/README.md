Spuštění aplikace: create_app (factory.py) drží middleware původu a hosta, obsluhu chyb, mount dist/ a skládá routery z api/ v pořadí aplikace → krok 1 → Projekt → Editor → Live Run. Žádné inline routy.

Vzdálený přístup (remote_access.py): jediné místo, které rozhoduje o požadavku z veřejného hosta za tunelem. Režim je aktivní jen s oběma proměnnými `OPORA_PUBLIC_HOSTS` a `OPORA_ACCESS_TOKEN`; jinak je hranice přesně dnešní loopback. Pro veřejný Host platí token na každé `/api/*` (Bearer nebo cookie `opora_access`), Origin proti `https://host` podle `X-Forwarded-Proto` a natvrdo 403 na `/api/agent-hooks/event|ack`, protože hooky řídí procesy na tomto počítači. Router `/api/access/{status,login,logout}` je v `backend/api/access_routes.py` a bere si z tohoto modulu jen porovnání tokenu a cookie. Kontext: `docs/vzdaleny-pristup.md`.

Řízení agenta (Hook control v1): factory zapojuje `/api/code-intelligence` (LSP-first, stav sémantiky bere z reálné služby přes injected callable), `/api/semantic-search` (lokální ONNX embeddings, žádný download za běhu) a `/api/agent-hooks` včetně `/vscode` (installer dostává veřejný binding z `HookControl.public_binding`, nikdy token). Aplikace žádný model nespouští; sémantický worker běží jen na explicitní dotaz.
