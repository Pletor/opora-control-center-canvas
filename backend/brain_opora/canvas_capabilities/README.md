## Boundary and native reuse

`GET /api/brain/canvas/capabilities`, `GET /api/brain/canvas/capabilities/{operation_id}` and `POST /api/brain/canvas/invoke` require a verified Heart token with the exact requested project and workspace. The invoke envelope is `{project, workspace, capability, input, requestId?}`. `capability` is a named finite operation; `requestId` is the stable native write receipt key. There is no caller-supplied URL, callable, actor or organization. This repository has projects/workspaces, not an organization authorization model.

Adapters use native Canvas/proposal/document, Desktop, site, research, vault and flow services. Read fields are bounded and typed; complex flow inspection uses native Pydantic request models and validators. Accepted graph and content edits persist native proposals; the catalog never calls acceptance. `opora_graph_routes.accept` prepares an existing immutable proposal and real review URL with `awaiting_human`, not a fabricated approval.

`canvas_routes.canvas_plan` is conditional: with no accepted baseline it uses native `apply_plan` and its existing receipt/readback to create a working draft; with an accepted baseline it creates a pending native graph proposal. Initial context is checked under the graph lock and receipt replay precedes stale context checks. `subject` labels proposals only; initial native receipt identity covers the actual native mutation payload. `researchSource` delegates to the native typed source-pin handling. This does not claim distributed Git/SQLite crash atomicity; incomplete native receipts retain their existing explicit recovery refusal.

Private `session_view.read/update` stores intent under project/workspace/token session ID, with revision CAS and scoped replay. The update receipt proves durable intent; a fresh read reports applied only when a live explicitly attached human tab acknowledged the current revision and exact view. Attachment isolation and browser evidence are documented in `frontend/editor/canvas/session-view/README.md`; these adapter tests do not substitute for that UI proof.

The legacy token guard runs before human-cookie authority: supplied invalid/revoked tokens fail401; foreign project/workspace and ID-only flow targets fail403 even with the write gate off. Genuine no-token local UI semantics remain. Existing main Heart to saved active workspace delegation is explicit in the legacy guard; the new catalog remains exact scope.

Shared library metadata is not uniformly safe: native detail includes foreign adoption names/project IDs, and summaries include learned/derived provenance. Unscoped legacy token reads of global workflow metadata are refused. The finite library list/detail adapters now provide a scoped lineage projection: they retain complete published graphs/versions, hide structured foreign learned/proposed/source references, and calculate visible derivation counts from own or published library workflows. Responses label `lineageScope` explicitly. Native shared library brief is an audited exception because it renders the published graph without that adoption metadata. No organization isolation claim is inferred from this project-token boundary.
